>Windows Event Logs are records of activities and events that occur within the Windows operating system.

They help administrators and security professionals monitor system activity, troubleshoot problems, and investigate security incidents.

Examples:

- Successful user logins.
- Failed login attempts.
- Application errors.
- Service startup and shutdown.
- System warnings.
- Security-related activities.

## 2. Windows Event Viewer

**Event Viewer** is a built-in Windows tool used to view and analyse event logs.

To open it:

1. Press `Win + R`.
2. Type `eventvwr.msc`.
3. Press Enter.

Event Viewer organises events into different logs.

## 3. Main Types of Event Logs

|Log|Purpose|
|---|---|
|Application|Records events generated by applications|
|Security|Records security-related events, depending on audit configuration|
|System|Records events generated by Windows components|
|Setup|Records Windows installation and setup events|
|Forwarded Events|Stores events collected from other computers|

## 4. Event Severity Levels

|Level|Meaning|
|---|---|
|Critical|Indicates a serious failure|
|Error|Indicates a significant problem|
|Warning|Indicates a potential problem|
|Information|Records normal operations|
|Verbose|Provides detailed diagnostic information|

An event's severity does not automatically indicate whether it is malicious.

## 5. Important Windows Security Event IDs

An **Event ID** identifies a particular type of event generated by a Windows event provider.

|Event ID|Description|
|---|---|
|4624|Successful logon|
|4625|Failed logon|
|4634|Account logoff|
|4648|Logon attempted using explicit credentials|
|4672|Special privileges assigned to a new logon|
|4688|A new process has been created|
|4720|User account created|
|4722|User account enabled|
|4726|User account deleted|
|4732|Member added to a security-enabled local group|
|4740|User account locked out|
|1102|Security audit log cleared|

**Important:** These events are useful only when the relevant auditing is enabled and the events are actually recorded. Event IDs must be interpreted with their surrounding context.

## 6. Important Event Information

An event record may contain:

- Event ID
- Date and time
- Source
- Level
- User or account
- Computer name
- Log name
- Description
- Additional event-specific details

These details help investigators reconstruct activity.

## 7. Cybersecurity Importance

Windows Event Logs are useful for:

- Investigating failed login attempts.
- Identifying suspicious account activity.
- Tracking account creation.
- Investigating privilege changes.
- Reviewing process creation.
- Detecting possible security incidents.
- Supporting digital forensic investigations.

### Example: Investigating Failed Logins

Suppose several failed login attempts appear in the Security log.

An investigator should examine:

1. Account name.
2. Time of each attempt.
3. Source IP address, when recorded.
4. Logon type.
5. Whether a successful login followed.
6. Whether the activity matches expected behaviour.

Multiple failed logins alone do not prove a brute-force attack.

## 8. Practical: Inspect Event Logs Using PowerShell

### Task 1: List Available Event Logs

```
Get-WinEvent -ListLog *
```

### Task 2: Read Recent System Events

```
Get-WinEvent -LogName System -MaxEvents 10
```

### Task 3: Read Recent Application Events

```
Get-WinEvent -LogName Application -MaxEvents 10
```

### Task 4: Search for Successful Logons

```
Get-WinEvent -FilterHashtable @{
    LogName = 'Security'
    Id = 4624
} -MaxEvents 10
```

### Task 5: Search for Failed Logons

```
Get-WinEvent -FilterHashtable @{
    LogName = 'Security'
    Id = 4625
} -MaxEvents 10
```

Security log access may require an elevated PowerShell session. If access is denied, record that observation rather than changing security settings.

### Task 6: Display Important Event Fields

```
Get-WinEvent -FilterHashtable @{
    LogName = 'Security'
    Id = 4625
} -MaxEvents 5 |
Select-Object TimeCreated, Id, ProviderName, Message
```

## 9. Important Commands

> Fundamental principles used to design and maintain secure systems.

## 1. Principle of Least Privilege (PoLP)

Users should receive only the permissions necessary to perform their tasks.

**Example:** A normal employee should not have administrator privileges.

## 2. Defense in Depth

Using multiple layers of security to protect systems and information.

**Example:**

- Firewall
- Antivirus
- Multi-factor authentication
- Network segmentation
- Regular backups

## 3. Zero Trust

A security approach based on the idea of never automatically trusting a user or device.

Every access request must be verified according to identity, device, context, and policy.

**Example:** An employee must authenticate again before accessing a sensitive application.

## 4. Separation of Duties

Dividing important responsibilities among multiple people to reduce mistakes and misuse.

**Example:** One employee initiates a financial transaction, while another approves it.

## 5. Fail-Safe Defaults

Access should be denied by default unless explicitly permitted.

**Example:** A newly created user account should not automatically receive access to confidential files.

## 6. Security Through Obscurity

Relying on secrecy of system design or implementation as a security measure.

**Important:** Obscurity alone is not a reliable security strategy. Strong security should not depend on hiding how a system works.

## 7. Regular Updates and Patching

Keeping operating systems and applications updated to fix known vulnerabilities.

**Example:** Installing Windows security updates.

## 8. Summary

|Principle|Main Idea|
|---|---|
|Least Privilege|Minimum required permissions|
|Defense in Depth|Multiple security layers|
|Zero Trust|Verify every access request|
|Separation of Duties|Divide responsibilities|
|Fail-Safe Defaults|Deny access unless permitted|
|Security Through Obscurity|Hiding implementation details|
|Updates and Patching|Fix known vulnerabilities|
